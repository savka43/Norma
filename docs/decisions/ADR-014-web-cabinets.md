# ADR-014 — Веб-кабинеты студента и руководителя

**Дата:** 2026-11-23. **Статус:** реализовано в пределах текущего инкремента.

Кабинеты используют React Router для адресов, TanStack Query для серверных
данных, TanStack Form для форм и CSS Modules для стилей. В корневом `src/`
приложение организовано по задачам в `features/`. Типы API генерируются из
OpenAPI. Cookie остаётся HttpOnly, изменяющие запросы отправляют заголовок
CSRF, а выход очищает кеш данных кабинета. Nginx обслуживает статическую
сборку и передаёт `/api/v1/` в FastAPI с того же origin. В разработке ту же
роль выполняет Vite proxy.

У студента есть одна ВКР. Вход и маршрут `/works` открывают её карточку,
когда работа назначена. До назначения там доступно состояние ожидания
с ручным обновлением. Для входа, регистрации и студенческого кабинета принят
пакет NORMA v0.1 от 27.11.2026 в `docs/design/`. Палитра, размеры и типографика
берутся из `src/tokens.css`. Каталог использует ссылку на тот же файл. IBM Plex
Sans с кириллицей входит в сборку приложения через Fontsource.

Форма регистрации собирает фамилию, имя и необязательное отчество в серверное
`full_name`. Профиль показывает это поле целиком, что сохраняет имена ранее
зарегистрированных пользователей в исходном виде. Email, роль и группа приходят
из `/auth/me`. Самообслуживание паролей, редактирование реквизитов и почтовые
настройки требуют отдельных серверных операций. Лента событий также пока недоступна.

Шапка студента ведёт в ВКР, редактор, проверки и материалы. Редактор имеет
отдельную оболочку и обратную ссылку. Материалами в этом инкременте служат
опубликованные шаблоны оформления группы. Список файлов кафедры в API отсутствует.
Обзор показывает тему и фактический срок, открытые замечания к отправкам и
ближайшие сроки этапов. Число сегментов соответствует назначенному плану,
текущим ориентиром служит первый незавершённый этап по порядку. Индикатор
не меняет статусы или формулу прогресса. Фиксированные этапы из демонстрационного
каталога не создаются. Имя руководителя отсутствует в ответе о ВКР.
У руководителя доступны группы, работы и шаблоны.

Студент может подготовить текст для отправки через существующий импорт
DOCX. Этот путь нужен для проверки этапов до появления редактора Lexical.
Браузер берёт аренду только на загрузку или отправку и освобождает её после
ответа. Замена рабочего текста требует подтверждения. При проверке всего
документа доступность действий определяется состоянием этапов и повторно
проверяется сервером.

Кабинет показывает текст сохранённой отправки и выделение цитаты. Для
привязки используются пути и диапазоны UTF-16 той же версии, что и у API.
DOCX/PDF этой версии можно скачать для просмотра структуры и иллюстраций.
Решение руководителя доступно в актуальной отправке. Оно передаёт ревизию
плана и UUID версии. Параметры оформления пока задаются через предустановку,
которую руководитель может добавить студентам.

Проверки заимствований отображаются в истории версии. Кнопка запуска
требует отдельного подтверждения для демонстрационного текста. Пока
попытка выполняется, браузер опрашивает защищённый маршрут. Серверный
worker продолжает проверку после закрытия браузера. Ошибка не запускает
новый POST автоматически.

Границы инкремента: редактор Lexical, страницы A4, редактирование отдельных
глав при проверке, параметры ГОСТ и интерфейс diff остаются отдельными
задачами по roadmap. Текстовый просмотр не воспроизводит разметку Word.
