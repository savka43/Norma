# ADR-002 — Тестовое API «Антиплагиат» для проверки workflow

**Статус:** принято пользователем. **Дата:** 2026-11-15.

## Контекст

ЛР1 (с. 3–5, 7) содержит прецедент проверки на антиплагиат; ЛР2
(с. 6, 9) содержит класс `ПроверкаАнтиплагиат` и связь с версией работы.
Пользователь получил согласование использовать тестовое API с ограниченной базой
для демонстрации **работающей интеграции**, а не научной оценки оригинальности.

## Решение

Использовать официальное SOAP/WSDL API:
`https://api.antiplagiat.ru:4959/apiCorp/testapi?wsdl`
(источник: https://docs.antiplagiat.ru/ru/api/).

- Реализовать `plagiarism/client.py` (SOAP-адаптер), `service.py` (оркестрация),
  `crud.py` (история проверок), `views.py` (HTTP статусы и команды).
- Отправлять на проверку **зафиксированную версию** (файл допустимого формата,
  сформированный из редактора); не отправлять незаписанный текущий текст.
- Сохранить статус, внешний ID, дату, доступные проценты и отчёты.
- Внешнюю проверку проводить асинхронно, с долговечным заданием и worker,
  чтобы результат стал доступен и после закрытия браузера.
- После ошибки не делать автоматической повторной загрузки/проверки;
  дать ручную повторную попытку. Отображать фазы и ошибки.
- Внешнему API передавать валидный `ExternalUserId` (не длиннее 40 символов).
- Конфигурация подключения — через защищённые настройки; **не** хранить
  публичные тестовые логин/пароль в репозитории или коде.
- Общий тестовый аккаунт не использовать для настоящих ВКР или персональных данных.

## Не является целью

Точная оценка по полной коммерческой базе, локальный алгоритм антиплагиата,
создание собственной поисковой коллекции. Ограниченная тестовая база достаточна
для учебной демонстрации проверки и пользовательского процесса.

## Источник

https://docs.antiplagiat.ru/ru/api/ — проверен 15.11.2026.
Документация требует асинхронности, отображения фаз, корректной обработки ошибок,
работы с доступными отчётами и внешним идентификатором пользователя.

## Реализация backend фазы 7

**Дата:** 2026-11-23.

- В `PlagiarismCheck` хранится одна попытка проверки. Она же служит записью
  очереди. Создание привязано к неизменяемой версии. Повтор после терминального
  статуса создаёт новую попытку. Частичный уникальный индекс разрешает максимум
  одну активную попытку на версию. Миграция `0010_plagiarism_checks` защищает
  источник, внешний ID и завершённые записи от UPDATE, а откат с историей
  проверок отклоняется.
- API возвращает `202` после commit. Отдельный Compose worker забирает задания
  через `FOR UPDATE SKIP LOCKED`, сохраняет фазу и временное право обработки,
  затем обращается к SOAP без открытой транзакции. Внешний ID фиксируется
  между загрузкой и запуском. При потере процесса polling продолжается
  после истечения блокировки. Прерванные загрузка и запуск имеют неопределённый
  внешний исход и завершаются ошибкой `interrupted`. Попытка не посылается
  повторно. Идентификатор захвата защищает от поздней записи старого worker.
- SOAP 1.1 отправляет UTF-8 TXT из блоков снимка, включая текст таблиц, списков
  и подписей. Изображения, оформление, имя студента и исходный DOCX не передаются.
  Имя файла служебное, `ExternalUserID` — UUID студента, индексация выключена.
  Пустой текст и превышение необязательного локального лимита отклоняются до
  отправки. Параметры времени задаются в окружении.
- Для тестового аккаунта интеграция по умолчанию выключена. Включение требует
  технических учётных данных и демонстрационного окружения. Каждый POST требует
  явного подтверждения, что версия содержит только искусственный текст.
  Подтверждение не классифицирует документ автоматически.
- Worker сохраняет доступные проценты, подозрительность, номер и ссылки
  на краткий отчёт и полный отчёт для чтения. Отсутствующие поля остаются
  `null`. Редактируемый отчёт, PDF отчёта и справка в этот инкремент не входят.
  Метрики хранятся локально, доступность внешней ссылки зависит от поставщика.
  Отчёт видят студент этой ВКР и её руководитель.

Контракт проверен по [WSDL и документации](https://docs.antiplagiat.ru/ru/api/).
`CheckDocument` имеет пустое выходное сообщение, а `GetCheckStatus` возвращает
`Summary` после готовности. Если `Summary` отсутствует, используется
`GetReportView`. Для рабочего клиента нужны настроенные HTTPS адреса.
