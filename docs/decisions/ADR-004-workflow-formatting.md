# ADR-004 — Принятые правила этапов, регистрации, оформления и истории

**Статус:** принято пользователем. **Дата:** 2026-11-16. Эти детали являются расширениями/уточнениями ЛР №1/№2, а не буквальными цитатами.

- Студент самостоятельно регистрируется; руководитель добавляет зарегистрированного студента в свою группу. Академическая группа не тождественна группе руководителя. Учётная запись руководителя создаётся через начальный bootstrap без добавления третьей бизнес-роли.
- Этапы создаёт и планирует руководитель, **все обязательны**. Невозможно подтвердить этап без явного действия руководителя.
- Статусы: `in_progress`, `in_review`, `changes_requested`, `completed`. Подтверждение только из `in_review`; исправленный этап подаётся повторно. История переходов неизменяема. Завершённый этап не открывается автоматически.
- Прогресс = `completed / total * 100%`, где `total > 0`. Нет весов. Изменения списка этапов после начала работы должны аудироваться; нельзя удалить завершённый этап с потерей истории.
- При отправке на проверку фиксируется version snapshot, а не живой текст. Замечания относятся к конкретной версии/фрагменту; закрытые замечания скрыты по умолчанию, но доступны в истории. При потере фрагмента ссылка становится неактивной, не удаляя цитату.
- Любые две сохранённые версии можно сравнить (added/removed/changed), перемещения — по возможности; diff не обязан быть идеальным.
- Базовый шаблон ориентирован на **ГОСТ 7.32-2017**, но проверка и экспорт всегда применяют настраиваемую сохранённую версию параметров (семантические стили и размеры).
- Проверка заимствований использует тестовое официальное API «Антиплагиат» для workflow, сокращённая база достаточна. Лимиты и форматы не выдумывать, настраивать и обрабатывать ответы API.
- AI/ML-помощник для подгонки текста к страницам сейчас **не нужен**.
