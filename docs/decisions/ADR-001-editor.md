# ADR-001 — Lexical и минималистичный постраничный редактор ВКР

**Статус:** принято пользователем. **Дата изменения:** 2026-11-16. Заменяет прежнее решение использовать Tiptap.

## Контекст

Исходные ЛР описывают загрузку версий и автоматическое оформление ВКР; пользователь уточнил необходимость встроенного редактора, который **сразу форматирует текст правильно**, отображает его по листам A4 и нормализует импортированные DOCX. Полноценный Word клонировать не нужно. Последовательное редактирование, не real-time.

## Решение

- React + TypeScript + **Lexical (`lexical`, `@lexical/react`)** как ядро редактирования. Tiptap **не используем**.
- Единый Lexical JSON (`JSONB`), `schema_version`, контроль ревизий, автосохранение, edit lease, immutable-версии и diff.
- Листы A4 **визуально** формируются отдельным pagination/layout слоем, не отдельными текстами страниц. Текст должен перетекать при правках и смене шаблона.
- Основные операции семантические: стили заголовка/основного текста/подписей, списки, изображения и таблицы; оформление определяется версией шаблона.
- Импорт DOCX сохраняет оригинал и строит нормализованное редактируемое содержимое; предупреждения о неподдержанных объектах.
- Экспорт DOCX/PDF из контрольной версии и зафиксированных параметров шаблона.
- Комментарии к версии/фрагменту; закрытые скрыты по умолчанию, исторические доступны; diff показывает удалённые фрагменты.
- Не делать отдельный throwaway-прототип. Технические риски проверять в ходе первой реализации редактора тестами/демонстрационными документами.

## Риски и компромиссы

Lexical не имеет готовой полной Word-постраничности; пользовательская pagination и гарантированный DOCX round-trip — **сложные задачи**. Нельзя считать их решёнными выбором библиотеки. Изолировать page layout engine, тестировать переполнение, таблицы, cursor/selection, экспорт. ML/LLM-помощник для пограничных переносов — идея на будущее, вне текущего объёма.

См. `docs/requirements/editor.md`, `docs/architecture/editor-design.md` и https://lexical.dev/docs/intro/.
