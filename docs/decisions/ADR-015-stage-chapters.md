# ADR-015 — Привязка этапов к главам документа

**Статус:** принято для backend фазы 6.

**Дата:** 2026-11-23.

Этап с привязкой к главе блокирует изменения этой главы до решения руководителя.
JSON Lexical schema v4 хранит UUID этапа в NodeState `normaStageId` на
верхнеуровневом `h1`. У этапа может быть одна глава. Область начинается с
заголовка и заканчивается перед следующим верхнеуровневым `h1`, в том числе
без привязки, либо в конце документа. `h2`–`h6` входят в состав главы.
Студент назначает привязку при сохранении. Backend проверяет принадлежность
этапа ВКР и структуру маркеров. В планировании, статусах и правах на решение
об этапе действуют прежние правила. Формат поля `$` соответствует
[сериализации NodeState Lexical](https://lexical.dev/docs/getting-started/node-state).

Отправка атомарно сохраняет полный контрольный снимок, выбранную версию шаблона
и `StageSubmission.scope`. Для этапа с привязкой scope равен `chapter`, без неё
и у отправок, созданных до миграции, — `document`. Полный снимок сохраняет
контекст и пути замечаний. Для `chapter` нужная область определяется в этом
снимке по UUID этапа независимо от дальнейших изменений рабочей версии.
Миграция `0011_stage_chapters` поддерживает v1–v4 без переписывания снимков.
Откат запрещён при наличии v4 или отправки главы.

Сохранение, восстановление и применение оформления сравнивают блоки всех
защищённых глав, их взаимный порядок, свойства корня и версию шаблона. Вставки
в соседних областях могут сдвигать позицию главы в документе. Разделение главы
новым `h1`, удаление заголовка или изменение содержимого защищённой главы даёт
`409`. Привязка через UUID сохраняется при правках вне главы. DOCX import
заменяет весь документ и блокируется при любой активной проверке. Одна проверка
со `scope=document` блокирует все пути записи содержимого, даже при наличии
других активных проверок глав. DOCX/PDF экспортирует полный снимок. При
повторном импорте DOCX этапы можно привязать заново.

Проверка области выполняется под блокировкой документа, общей с отправкой и
решением. Сравнение с предыдущим рабочим JSON сохраняет неизменность защищённых
блоков от момента отправки до решения. Lease и ревизия проверяются перед
мутацией. Восстановление и нормализация сохраняют снимки только после успешной
проверки; отказ не создаёт записей истории.
