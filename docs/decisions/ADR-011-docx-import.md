# ADR-011 — Ограниченный импорт OOXML, исходники и Lexical schema v2

**Дата:** 2026-11-21. **Статус:** принято для первого backend-инкремента фазы 5.
Основания: UC-01/FR-01, ED-08/10/13, требования безопасности импорта и ADR-010.

## Решение

`POST /documents/{document_id}/import` принимает DOCX бинарным телом с точным
типом содержимого, `expected_revision`, `confirm_replace=true`, CSRF и арендой.
Так сервер ограничивает чтение тела до разбора и при chunked-загрузке. Multipart
и предварительный upload/preview не добавляются в этот инкремент. До отправки
frontend должен показать подтверждение замены; без явного флага API даёт `422`.

Прямой разбор OOXML через `zipfile` и `defusedxml` сохраняет структуру абзацев,
заголовков (outlineLvl и наследование стилей), базовое выделение, обычные и вложенные
списки (numId/ilvl/start/override), типовые таблицы и PNG/JPEG. HTML не создаётся.
Произвольные исходные шрифты/размеры/поля не импортируются в inline CSS:
семантика связана с уже выбранной неизменяемой версией шаблона. Это подготовка
нормализованного содержимого; визуальное применение шаблона и ГОСТ-проверки ещё
не реализованы. На Word-совместимую пагинацию этот инкремент не претендует.

ZIP не извлекается в файловую систему. Сервер отвергает абсолютные/обратные пути,
`..`, дубликаты, симлинки, шифрование, неподдержанные методы сжатия, повреждения
ZIP/CRC, DTD/сущности, макросные типы и пакеты без стандартной основной части DOCX.
Используется transitional OOXML; strict OOXML с другими пространствами имён пока
даёт `422`. Внешние relationships не загружаются. XML проверяется потоком с лимитами
во время построения дерева. Стили, numbering и relationships индексируются;
циклы наследования стилей отвергаются, глубина цепочки ограничена 32.

Технические лимиты первой реализации (не взяты из ЛР): исходник **10 MiB**,
до 1000 ZIP entries, 50 MiB суммарно после распаковки, 8 MiB на часть,
коэффициент сжатия до 200, 100 000 XML-элементов на пакет и 64 уровня XML.
Изображение — до 20 млн пикселей, сумма перекодированных изображений — до 10 MiB.
Действуют прежние лимиты Lexical JSON из ADR-010. Кодировки HTTP-body, кроме
identity, отвергаются. Лимиты пока константы; превышение upload — `413`, неверный
media type — `415`, неверный/слишком сложный пакет — `422`.

Pillow декодирует только PNG/JPEG, затем записывает новый PNG без исходных
метаданных. Asset содержит UUID, размеры и серверный media type. SVG, VML,
повреждённые и внешние изображения не рендерятся; выдаётся предупреждение.
Исходные размеры размещения/обтекание/кроп рисунка не переносятся как Word-layout.

## Схема и хранение

Schema v1 продолжает поддерживаться без переписывания старых снимков.
Schema v2 добавляет штатные Lexical `table/tablerow/tablecell` и inline custom node
`norma-image {version: 1, asset_id: UUID, alt_text}`. У изображения нет произвольного URL
или HTML; backend проверяет принадлежность всех image UUID этому документу при save.
Таблица — прямоугольная, до 100 столбцов/1000 строк; горизонтальные объединения
поддержаны, вертикальные нормализуются до rowSpan=1 с предупреждением. Короткие
строки дополняются пустой ячейкой; вложенная таблица превращается в последовательность
блоков своей ячейки с предупреждением. Свободный CSS/цвета/размеры не принимаются.

`DocumentImport` хранит оригинальные байты, размер/SHA-256, автора, warnings,
ссылки на снимки до и после импорта. `DocumentAsset` хранит обработанные изображения.
Данные — отдельные PostgreSQL BYTEA, не внутри JSON. При выбранных лимитах это
минимальная долговечная реализация: одна транзакция, существующие backup/права,
нет потерянных файлов при rollback и нового внешнего хранилища/volume.
Binary-поля deferred, в списках метаданных не загружаются. При больших объёмах
перенос blobs в object storage потребует отдельного решения и политики очистки.

Разбор выполняется в thread pool до row lock. После разбора сервер берёт блокировку
документа, перечитывает его и повторно проверяет аренду/revision по времени БД.
В одной транзакции создаёт защитный снимок черновика, заменяет content, увеличивает
revision на 1, создаёт импортированную контрольную версию и записывает исходник/assets.
Шаблон сохраняется прежний, счётчик контрольных версий увеличивается на 2.
Повтор старого запроса — `409`, повторной записи исходника нет. Ошибка не должна
оставлять частичный импорт. Старые снимки/исходники/assets не изменяются; UPDATE
источника и assets запрещён PostgreSQL тем же immutable-trigger, что версии.

Исходник скачивается только как attachment с серверным UUID-именем, `no-store`
и `nosniff`. Изображение — только PNG с `nosniff`, `no-store`, CSP sandbox.
Чтение — студенту своей ВКР и её руководителю, изменение — только студенту;
во всех запросах UUID дополнительно ограничивается document_id. Исходник/картинки
остаются доступны для истории после замены рабочего текста и восстановления.

Откат миграции к schema v1 запрещён, пока есть рабочие документы или снимки v2;
он не удаляет импортированный текст и не переписывает неизменяемые версии.

## Предупреждения и ограничения

API возвращает и хранит `warnings: {code: count}`. Коды известны клиенту:
`formatting_normalized_to_template`, `image_layout_normalized`,
`unsupported_image`, `drawing_not_imported`, `external_relationship_ignored`,
`nested_table_flattened`, `vertical_merge_normalized`, `irregular_table_normalized`,
`unknown_style`, `unknown_numbering`, `numbering_format_normalized`,
`list_depth_normalized`, `heading_level_normalized`, `page_break_normalized`,
`section_break_normalized`, `unsupported_inline`, `unsupported_block`.
`unsupported_part_{header|footer|footnotes|endnotes|comments|embeddings}` сообщает
об отдельных неподдержанных частях. Для встреченных элементов используются
`unsupported_{hyperlink|fldSimple|fldChar|instrText|footnoteReference|endnoteReference|
oMath|oMathPara|pict|object|ins|del|sdt|commentRangeStart|commentRangeEnd|commentReference}`.

Поля Word сохраняют доступный отображаемый текст, формулы — доступный текст
без математической вёрстки, hyperlinks — подпись без URL. Текст вставок/удалений
tracked changes сохраняется как обычный текст с предупреждением, не как принятые
изменения Word. Сноски, колонтитулы, сложные объекты/диаграммы и другие неподдержанные
части остаются в оригинале. Произвольный DOCX не обещает lossless round-trip.
UI предупреждений/редактор/A4, экспорт DOCX/PDF и проверка оформления ещё отсутствуют.

## Проверка и источники

Тестируются корректные/опасные пакеты, реальные фикстуры `python-docx` и
Lexical 0.53.0 (`@lexical/table` и сериализационная заглушка custom image node),
HTTP/JSONB round-trip, права/CSRF, аренда/ревизии, снимки, неизменность blobs,
повтор запроса и гонки import/import, import/save, import/restore на PostgreSQL.
Сериализационная заглушка не является готовым frontend-рендерером изображения.

Структура таблиц — [Microsoft OOXML](https://learn.microsoft.com/en-us/office/open-xml/word/working-with-wordprocessingml-tables),
риски распаковки — [Python zipfile](https://docs.python.org/3.12/library/zipfile.html#decompression-pitfalls).
Реальные команды и результаты — в [roadmap](../plans/roadmap.md),
HTTP-поля — в [API-контракте](../architecture/api-contract.md).
