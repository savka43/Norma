# ADR-012 — Семантическое оформление и экспорт контрольных версий

Статус: принято техническое решение. Дата: 2026-11-22.

## Решение

Оформление вычисляется по семантическому типу блока и неизменяемой
`FormattingTemplateVersion`, связанной с контрольной версией. Размеры/интервалы
не дублируются в Lexical JSON. Заголовки используют соответствующий уровень,
списки — `list`, обычные абзацы ячеек — `table`, подписи — `caption`, прочие
абзацы/цитаты — `body`. Абзац только с рисунками использует параметры `caption`
(в том числе выравнивание и отступ), чтобы не наследовать отступ основного текста.
Параметры выбранного шаблона определяют геометрию листа,
шрифт, размер, интервалы, выравнивание, абзацный отступ, bold/italic и начало
нумерации. ГОСТ-предустановка — редактируемая отправная точка, не сертификат
полного соответствия стандарту или требованиям конкретного вуза.

Schema v3 добавляет `norma-caption` с `kind: figure|table` и обычными inline-узлами.
V1/v2 читаются без изменений, подписи нельзя выдавать за старую схему. Миграция
`0008_semantic_captions` расширяет CHECK; downgrade запрещён при наличии v3.
Экспорт использует отдельные стили `Norma Figure Caption`/`Norma Table Caption`;
повторный импорт этих стилей сохраняет вид подписи и выбирает schema v3.
Произвольные подписи Word по тексту не угадываются.

## Проверка и применение

`format-check` проверяет семантический JSON против **его** версии шаблона:
конфликтующее явное выравнивание, ручной indent, кодовое/цветовое выделение
и преобразования регистра. В JSON уже запрещены произвольные шрифты, размеры,
CSS; параметры шрифтов/интервалов приходят из шаблона. Отчёт содержит параметры,
пути, actual/expected, общее число и первые 1000 отклонений. Это проверка
семантического оформления, не геометрический анализ страниц и не аудит исходного
DOCX. Проблемы неподдержанных исходных элементов остаются в предупреждениях импорта.

`apply-formatting` требует явного `confirm_apply: true`, роли владельца-студента,
доступной версии шаблона его руководителя, действующих lease/revision. Под row lock
в одной транзакции сохраняет защитный снимок, сбрасывает ручные overrides,
выбирает шаблон, увеличивает revision и сохраняет итоговый снимок. Текст,
порядок/типы блоков, структура списков/таблиц, изображения, жирный/курсив,
подчёркивание/зачёркивание, верхний/нижний индекс сохраняются. Старые версии
не обновляются. Повтор с прежней revision — `409` без лишних снимков.

## Экспорт

`POST /document-versions/{version_id}/exports` принимает только `format: docx|pdf`.
Студент своей ВКР и её руководитель могут скачать файл. Источник — сохранённая
версия + pinned template + принадлежащие документу assets, независимо от черновика
и более поздних шаблонов. Нельзя подставить другой шаблон в запрос экспорта.
Сервер завершает read-транзакцию до запуска преобразования в thread pool.
Сгенерированные файлы не сохраняются в БД: источник уже долговечен и неизменяем.

DOCX формирует python-docx: стили, A4/ориентация/поля, настоящая нумерация списков
с независимым start и уровнями, таблицы с colSpan, PNG и alt text, поле PAGE.
Ширина/высота рисунка ограничены печатной областью с учётом абзацного отступа.
Inline drawing явно задаёт нулевые distL/R/T/B: без них LibreOffice добавлял
3,2 мм бокового расстояния и сдвигал широкий рисунок за поле (проверено PDF).
Заголовок удерживается
со следующим блоком, подпись таблицы — с таблицей, подпись рисунка — с предыдущим
абзацем. Поддерживаются девять уровней списков, более глубокий экспорт — `422`.
В OOXML-адаптере локально отключены только проверки incomplete third-party
member/variable types и private handles: python-docx требует этих XML API для
нумерации/полей. Остальной backend проверяется BasedPyright strict.

PDF создаётся LibreOffice из **этого** DOCX. У каждого запроса отдельные временные
файлы и профиль. Таймаут настраивается (60 секунд по умолчанию), при таймауте
уничтожается отдельная группа процессов и очищается каталог. Только собственный
сгенерированный DOCX передаётся конвертеру; непроверенный оригинал туда не попадает.
Файл не содержит внешних relationships, макросов или HTML.

Два экспорта на процесс допускаются одновременно; занятость, отсутствующий или
ошибочный PDF-конвертер — `503`, без автоматического повтора. Ограничены объём
изображений с учётом повторений и размер результата (32 MiB). Ошибка не меняет
документ/историю. Экспорт — синхронный ограниченный запрос; долговечный worker
нужен будущему антиплагиату, он здесь не вводится.

Ответ — binary attachment с UUID-именем, no-store/nosniff, UUID версии документа
и шаблона. `X-Export-Warnings` сообщает `manual_formatting_normalized`, если
экспорт применил семантические правила поверх ручных overrides; исходный снимок
при этом не меняется. Для PDF `font_substitution` сообщает о недоступности
запрошенного семейства по fontconfig или невозможности проверить наличие шрифта.
В Docker установлены Liberation и DejaVu; Times New Roman может заменяться
Liberation Serif. DOCX сохраняет запрошенное семейство. Бинарная идентичность
повторных файлов и идентичность пагинации Word/браузера не обещаются.

## Проверка

Unit/API/DB: пользовательский текст и emphasis, custom параметры, геометрия и
OOXML-стили, подписи и повторный импорт, numbering/start, таблицы/assets,
неизменность исходных версий, права/CSRF, lease/revision, конкуренция
apply/apply, apply/save, apply/restore, миграции и запрет downgrade v3.
Реальный PDF проверяется в образе с LibreOffice, страницы синтетических короткого,
длинного и альбомного документов — отдельно визуально. Frontend/A4 не добавлены.

Источники API библиотек: [python-docx](https://python-docx.readthedocs.io/en/latest/api/document.html),
[стили python-docx](https://python-docx.readthedocs.io/en/stable/user/styles-using.html),
[параметры LibreOffice](https://help.libreoffice.org/latest/en-GB/text/shared/guide/start_parameters.html).
