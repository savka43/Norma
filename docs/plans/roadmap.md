# План реализации полного продукта (без отдельного прототипа)

Это **единственный действующий план разработки для всех агентов**. Правила работы —
в `AGENTS.md`, детали продукта — в связанных требованиях, архитектуре и ADR из `docs/`.
Корневые `PLAN.md` и `CLAUDE.md` только ссылаются на эти документы. Старые материалы
из `docs/archive/` не являются источником задач или требований.

Цель — **работающее приложение** по 12 UC из ЛР №1, а не MVP-демо. Реализацию вести вертикальными задачами: frontend + backend + БД + проверка. Сложный редактор создавать непосредственно внутри продуктового `frontend/src/features/document-editor`, не отдельным временным проектом.

## Учёт выполнения

В этом файле хранится и план, и контекст выполнения. Перед каждой задачей читать
«Текущий статус» и последние записи журнала. После каждой задачи обновлять статус
и добавлять запись в журнал со следующими сведениями:

- дата, фаза и задача;
- что фактически реализовано и какие UC/FR/ED/NFR покрыты, если применимо;
- основные изменённые файлы;
- реально выполненные команды проверок и их результаты; отдельно — что не проверено;
- оставшиеся ограничения, блокеры и ближайший шаг.

Частично выполненную задачу обозначать явно; фазу завершать только после
выполнения её критериев. Технические решения с обоснованием хранить в
`docs/decisions/`, команды запуска — в `docs/development.md`. `README.md` содержит
только картинку по решению пользователя. Не создавать отдельный
параллельный план или отчёт только в переписке.

## Работа над редактором

Пагинация Lexical и импорт DOCX — технические риски; реализуй их в фазах 4–5 и **не утверждай прохождение критериев без реального теста**. Если первая реализация умеет только визуальные рамки A4, она ещё не выполняет требование автоматического переноса между редактируемыми листами. При обнаружении ограничения выполни нужную доработку, документируй технический выбор, не заменяй функцию фиктивным макетом.
