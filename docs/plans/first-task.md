# Первое задание для Codex: начать с API

Скопируй следующий текст в Codex **из корня репозитория**:

> Прочитай `AGENTS.md`, `docs/requirements/product.md`, `docs/requirements/use-cases.md`, `docs/requirements/editor.md`, `docs/architecture/overview.md`, `docs/architecture/domain-model.md`, `docs/architecture/editor-design.md` и `docs/plans/roadmap.md`.
>
> **Начни с backend/API-части фазы 1**, согласно решению пользователя от 2026-11-17. Сначала проверь «Текущий статус» и «Журнал выполнения» в roadmap: не создавай заново уже реализованное. Это полноценная система сопровождения этапов ВКР на FastAPI + PostgreSQL + React + TypeScript. Исходных DOCX лабораторных в репозитории нет; их требования уже включены в спецификацию. **Не создавай отдельный прототип редактора и не ограничивайся планом.**
>
> Настрой `backend/` с `uv`, FastAPI, SQLAlchemy 2 async, Alembic, Pydantic, Ruff, BasedPyright и pytest; `compose.yaml` с PostgreSQL, backend и применением миграций; `.env.example` без секретов. Структура backend `app/api_v1/<feature>/views.py,schemas.py,crud.py,dependencies.py` по необходимости; `service.py` — для сложных правил, модели — в `app/core/models/`. Сделай healthcheck процесса и готовности БД, OpenAPI и базовые API/DB-тесты. Добавь команды запуска и проверок в `docs/development.md` (сохрани ссылки на спецификацию). Корневой `README.md` должен содержать только картинку по решению пользователя. Текущая задача ограничена основой API; auth и предметные маршруты — следующие задачи roadmap.
>
> Frontend в этой задаче не изменяй; его часть фазы 1 остаётся обязательной и учитывается отдельно. **Редактором будет Lexical, НЕ Tiptap.** Без Tailwind, shadcn/ui, React Hook Form и Zod. Не внедряй ML, real-time collaboration, нормоконтролёра и заведующего кафедрой.
>
> Сначала напиши короткий план изменений, затем **создай файлы и запусти доступные проверки**: Ruff, BasedPyright, pytest, Docker Compose config, сборку и запуск контейнеров, миграции и запросы к API. Пользователь разрешил локальный запуск контейнеров. Если Docker недоступен, явно об этом сообщи. Не утверждай, что тесты прошли, если не запускал их. Не создавай коммит и не делай push.
>
> По завершении обнови текущий статус и журнал в roadmap: созданные файлы, реально выполненные команды/результаты, покрытие требований, ограничения и следующий шаг. Не отмечай всю фазу 1 завершённой по готовности только backend. В итоговом ответе укажи адрес API и документации.
