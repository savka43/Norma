# Требования к редактору ВКР (проектная детализация UC-01, 02, 04, 06, 10)

**Статус:** согласованное целевое поведение. Основание предметной области: ЛР №1/№2; выбор UX/стека — решения пользователя от 16.11.2026. Это спецификация конечного продукта, **не задание на отдельный прототип**.

## 1. Цель

Редактор не должен превращаться в перегруженный Word. Пользователь пишет ВКР в минималистичном интерфейсе, а система сразу использует выбранные правила оформления либо исправляет оформление импортированного DOCX. Весь документ логически непрерывен, но **визуально разделён на листы A4**.

## 2. Обязательное поведение

| ID | Требование | Критерий приёмки |
|---|---|---|
| ED-01 | Открыть и редактировать документ как единое целое | Ввод текста, курсор, выделение, undo/redo и автосохранение работают без потери содержимого |
| ED-02 | Постраничное отображение A4 | Видны границы страниц, поля, номер страницы; при переполнении текст продолжает идти на следующий лист |
| ED-03 | Автокомпоновка при правках | Вставка/удаление абзаца выше меняет разбиение последующих страниц без потери порядка, выделения и текста |
| ED-04 | Минималистичный toolbar | Основные команды: стиль блока, жирный/курсив, списки, таблица, изображение, undo/redo; второстепенные настройки не перегружают вид |
| ED-05 | Семантические блоки | «Основной текст», «Заголовок N», «Подпись таблицы», «Подпись рисунка», таблица, изображение; параметры определяются шаблоном |
| ED-06 | Применение шаблона при наборе | Размер A4, поля, шрифт, интервал, абзац, заголовки и подписи отображаются согласно активной версии шаблона |
| ED-07 | Проверка/исправление оформления | Пользователь может запросить отчёт несоответствий и применить выбранный шаблон; пользовательский текст/порядок абзацев при исправлении не теряются |
| ED-08 | Импорт DOCX | Текст, заголовки, списки, типовые таблицы и изображения импортируются в структуру редактора; оригинал сохраняется отдельно; замеченные неподдержанные элементы указываются |
| ED-09 | Экспорт DOCX и PDF | Экспортируется неизменяемая версия с конкретной версией шаблона; документ можно открыть вне приложения |
| ED-10 | Версии | Доступны хронология, просмотр и восстановление сохранённого снимка с созданием новой версии (старые не переписываются) |
| ED-11 | Сравнение версий | Вставки, удаление, изменение подсвечены между выбранными версиями; исходный удалённый текст доступен |
| ED-12 | Комментарии | Руководитель оставляет замечание к версии и фрагменту; студент видит открытые замечания; закрытые скрыты по умолчанию, доступны в истории |
| ED-13 | Однопользовательское редактирование | Один активный редактор документа; server-side lease, `revision`, `409` при конфликте и сохранение несинхронизированного текста локально до ручного разрешения |
| ED-14 | Работа с этапами | Отправка этапа фиксирует immutable snapshot, руководитель проверяет именно его; после запроса правок можно редактировать вновь |

## 3. Постраничная модель

- Структура документа (Lexical JSON) **не делится на отдельные записи по странице**. Листы — вычисляемое представление на базе выбранного шаблона.
- Переносы работают при редактировании текста в середине и начале документа, при изменении полей и при импорте DOCX.
- При первом этапе реализации подготовить **продуктовый компонент редактора с минимальным измерением страниц**. Усложнять компоновку по мере появления типов содержимого (таблиц, изображений, подписей) и регрессионных тестов.
- Пагинация в браузере и финальная пагинация DOCX/PDF могут расходиться из-за рендеринга шрифтов и движка конвертации; такие различия выявлять тестами/визуальной проверкой. Не заявлять pixel-perfect соответствие Word без доказательства.
- Базовые детерминированные правила блоков (например, не оставлять заголовок один внизу страницы и по возможности держать подпись с объектом) — часть обычной верстки. **Умный ML-помощник для пограничных случаев** (перенос длинной подписи, изменение текста и т. п.) исключён из текущего объёма.

## 4. Импорт и нормализация DOCX

`DOCX → серверный разбор → семантические блоки → валидация/санитизация → Lexical JSON → применённый шаблон → редактирование`.

- Импорт **содержимого**, а не обязательное сохранение исходных случайных шрифтов и отступов.
- Минимальная поддержка: абзацы, заголовки, базовое выделение, маркированные/нумерованные списки, типовые таблицы, обычные изображения.
- Сложные вложенные таблицы, формулы Word OMML, поля Word, сноски, колонтитулы, разрывы разделов: поддержка не гарантируется до реализации и тестов. Не отбрасывать их молча; сохранять исходный DOCX и давать отчёт.
- Никогда не превращать непроверенный импортированный HTML в исполняемую разметку в браузере.
- Импорт не уничтожает текущую работу без подтверждения; после успешного импорта доступна новая контрольная версия.

## 5. Шаблон оформления

- По умолчанию предустановка, ориентированная на **ГОСТ 7.32-2017**. Конкретные значения параметров — **настройки**, а не жёстко прописанные константы проверки.
- Поля шаблона: формат листа, ориентация, поля (мм), семейство и размер шрифта, межстрочный интервал, отступ абзаца, интервалы до/после, правила заголовков, нумерация страниц, правила таблиц/подписей.
- Шаблон имеет `id`, `version` и неизменяемый snapshot параметров для истории версии и экспорта.
- При выборе другого шаблона изменения касаются отображения/экспорта, а не семантики текста.

## 6. Комментарии и diff

- Замечание привязано к immutable-версии, автору, текстовой цитате и по возможности к устойчивому идентификатору блока/позиции.
- Комментарий `open` → `resolved`; при исправлении студент может отметить его как устранённое. Отметка не означает подтверждение этапа: руководитель принимает решение отдельно.
- При удалении текста ссылка может стать `detached`, но комментарий и цитата сохраняются. Скрывать по умолчанию закрытые/устаревшие, предоставлять фильтр «Все» и доступ к исходной версии.
- Diff по семантическим блокам и тексту; перемещения — **best-effort**. Не прятать удалённый текст при сравнении.

## 7. Не делать сейчас

Реальное совместное редактирование, чат, WebSocket/Yjs, ML/LLM-подгонку текста под листы, гарантированную идентичность любому DOCX Word, произвольный конструктор шрифтов как основную функцию.
