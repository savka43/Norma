# Бизнес-прецеденты: 12 Use Case из ЛР №1

**Источник:** ЛР №1, раздел «Построение диаграммы вариантов использования», с. 6–8;
описание предметной области, с. 4–5.
Перечень и названия прецедентов взяты из ЛР; критерии приёмки ниже —
**проектная детализация**, а не цитата из лабораторной.

| ID | Прецедент (ЛР №1) | Основной актёр | Проверяемое поведение |
|---|---|---|---|
| UC-01 | Загрузить версию работы | Студент | DOCX импортирован в Lexical с нормализацией оформления; оригинал/история доступны; предупреждения об ошибках видны |
| UC-02 | Оформить работу по требованиям | Студент | Показано оформление на листах A4 по сохранённому настраиваемому шаблону; DOCX/PDF создаётся из снимка |
| UC-03 | Проверить работу на антиплагиат | Студент | Задание сохранено; статус обновляется; результат связан с версией и доступен позже |
| UC-04 | Просмотреть замечания | Студент | Видны замечания по доступной работе, автор, версия и статус исправления |
| UC-05 | Отправить этап на проверку | Студент | Создан immutable snapshot; статус `in_review`, руководитель видит отправку и проверяет именно снимок |
| UC-06 | Просмотреть версии работы | Студент и руководитель | Доступна хронология и diff любых двух версий; удалённый текст доступен; старые версии не переписываются |
| UC-07 | Сформировать группу студентов | Руководитель | Самостоятельно зарегистрированный студент добавлен руководителем в его группу; конфликт привязки отвергается |
| UC-08 | Настроить этапы и сроки | Руководитель | Создание/изменение списка этапов, порядка и сроков в допустимом состоянии |
| UC-09 | Проверить работу студента | Руководитель | Проверяемая версия доступна руководителю; действия проверки отражаются в истории |
| UC-10 | Оставить замечание | Руководитель | Замечание связано с версией и фрагментом, скрыто после разрешения по умолчанию, но доступно в истории |
| UC-11 | Подтвердить выполнение главы (этапа) | Руководитель | Руководитель явно переводит `in_review → completed`; все этапы обязательны; прогресс `completed/total × 100%` |
| UC-12 | Контролировать ход выполнения ВКР | Руководитель | Групповая сводка показывает этапы, сроки, подтверждения и просрочки |

## Заметки к реализации

- В исходной ЛР актёров два. «Просмотреть версии работы» — общий прецедент
  студента и руководителя (ЛР1, с. 8).
- «Оставить замечание» в диаграмме — необязательное расширение «Проверить работу
  студента» (`extend`, ЛР1, с. 8). Нельзя требовать замечание для каждой проверки.
- Научный руководитель выполняет функции администрирования своей группы;
  отдельный универсальный администратор не входит в исходную модель.
- ЛР описывает **загрузку** версий. Принятое позже веб-редактирование не отменяет UC-01:
  импорт DOCX следует реализовать и тестировать отдельно, согласовав его ограничения.
- «Проверить на антиплагиат» делегирует поиск внешнему API, а не локальному алгоритму.

## Сквозные приёмочные сценарии

**Сценарий А — этап от черновика до подтверждения:**
руководитель формирует группу → настраивает этапы/сроки → студент работает
в редакторе → создаёт/загружает версию → отправляет этап → руководитель
открывает зафиксированную версию → при необходимости оставляет замечание →
студент исправляет → руководитель явно подтверждает → прогресс обновляется.

**Сценарий Б — оформление и антиплагиат:**
студент выбирает зафиксированную версию → запускает оформление/экспорт →
получает DOCX/PDF → инициирует внешнюю проверку → закрывает браузер →
задание обрабатывается сервером → после нового входа отображается статус/результат.

**Сценарий В — права и история:**
чужой студент не открывает работу; руководитель видит только закреплённых
студентов; изменение рабочего JSON не портит предыдущие версии и связанные
с ними результаты проверок/замечания.

## Уточнённые приёмочные сценарии редактора (пользовательское дополнение)

**D — постраничный набор:** создать документ с текстом длиннее одного листа A4; убедиться, что текст идёт на следующий лист, вставка абзаца в начале перераспределяет текст, удаление возвращает его назад; cursor, выделение и undo работают. Не считать одну декоративную страницу доказательством результата.

**E — оформление / DOCX:** загрузить демонстрационный DOCX с заголовком, параграфом, таблицей и картинкой; увидеть нормализованное содержимое в редакторе. Изменить поле/шрифт в шаблоне и проверить, что отображение и DOCX/PDF используют новые параметры; предупреждения о неизвестных форматах отображаются.

**F — замечания / diff:** руководитель комментирует фрагмент версии 1, студент удаляет или переносит его, сохраняет версию 2; замечание остаётся в истории с исходной цитатой, а сравнение версий показывает исходное и новое состояние. Закрытые замечания не мешают основному виду.

**G — этапы:** из `in_progress` студент отправляет этап; руководитель возвращает `changes_requested`; студент дорабатывает и повторно отправляет; руководитель нажимает «Подтвердить»; этап становится `completed` и прогресс пересчитывается по числу всех обязательных этапов.
